# Try the Oak Gallerie working prototype

This is a practice workspace. Use dummy details and sample photos/videos. No real SMS, OTP, email, or push message is sent. Keep the same browser and address throughout the demonstration so everyone uses the same saved sample workspace.

## 1. Try the six logins

On the welcome screen, choose a person by role. You do not need a password. Use **Switch account** to try another person; your requests remain saved.

| Login card | What to look for |
|---|---|
| Admin / Owner | All requests, Staff directory, Reports, Delivery health, and demo controls |
| Manager / Team Lead | All requests, Reports, Delivery health, assignment actions, and demo controls |
| General Staff | Their relevant work and Service, Help ticket, and Follow-up creation |
| First Service Technician | Assigned service work and their personal Follow-ups |
| Second Service Technician | A different set of assigned service work and their personal Follow-ups |
| Support / Back-office | Help tickets, personal Follow-ups, and their assigned urgent messages |

The person's name and role appear in the header. Staff, technicians, and support cannot send an Urgent message or assign a request to another person. Only the Admin sees the Staff directory.

## 2. Demonstrate a complete Service request

1. Choose **General Staff**, then **New request** and **Service**.
2. Select one of the sample projects. Enter: “Dining chair arm is loose. Please arrange a repair visit.” Leave the request in the **Shared queue** and create it.
3. Switch to **Manager / Team Lead**. Open the request and assign it to the first Service Technician.
4. Switch to that **Service Technician**. Open the assigned request, choose **In Review**, and record: “Checked the customer photo. Visit planned tomorrow.” Add an expected timeline and save the update.
5. Add a small photo or video. Reopen the request to check the attachment and the activity trail. The upload should not change the time of the last workflow update.
6. Record another update to **Scheduled**, then **Resolved** after the sample repair. The timeline should retain creation, assignment, attachments, and each workflow change.
7. Switch back to **Manager** and open **Reports**. Confirm the totals and workload reflect the resolved request. An Admin or Manager can reopen it to **In Review** for another visit.

## 3. Try a Help ticket and a personal Follow-up

1. As **General Staff**, create a Help ticket: “Need the invoice copy for the Alipore dining table delivery.” Leave it in the shared queue.
2. As **Manager**, assign it to **Support / Back-office**. Switch to Support, add an update, then resolve it: “Invoice copy prepared and checked.”
3. As any person, create a Follow-up: “Call the customer to confirm the repair was satisfactory.” Choose a 12-hour reminder.
4. Confirm the Follow-up belongs to the person who created it. A technician can update and resolve their own Follow-up too.

## 4. Try an Urgent message

1. As **Manager**, create an Urgent message: “Please call the customer before today's dining table dispatch.” Select the second Service Technician as recipient.
2. Open it as another person with access. It must not let that person acknowledge on the recipient's behalf.
3. For the repeat example, leave it unacknowledged and use the Manager's **+15 minutes** demo control. Check the simulated repeat push/email activity and Delivery health.
4. Switch to the named **second Service Technician**. Opening the request records a read; it still needs acknowledgement.
5. Tap **Acknowledge**. The critical acknowledgement warning should disappear, and the activity trail should name the recipient. Acknowledgement alone does not resolve the task or reset its 24-hour update clock.

## 5. See the 24-hour reminder without waiting a day

1. As **Manager**, create or assign a fresh request to a staff member. Note its last workflow update time.
2. Use **+24 hours** in the demo controls. The open request should become overdue and show reminder activity for its assigned person.
3. Try an unassigned request too: its 24-hour reminder belongs to the person who created it.
4. Switch to the responsible person and record a permitted workflow update. The overdue warning clears and a fresh 24-hour period begins.
5. Opening a request, uploading a photo, changing its assignee, and acknowledging an urgent message must not clear the overdue warning. Resolving a request stops pending reminders.

The time controls advance all requests in this saved demo. They do not change your computer's clock. You can also use them to make the personal Follow-up from step 3 become due. Delivery results are simulations that you inspect inside the app.

## 6. Review and start again

1. As **Admin**, open the Staff directory and check all six people, their roles, and their current workload.
2. As **Admin** or **Manager**, open Reports and Delivery health. Inspect the sample successes, retry states, and failures; none of these send a real message.
3. Switch accounts and refresh the browser. Requests, updates, the demo clock, and locally uploaded attachments should remain available.
4. Use **Reset demo** when ready to start over. Confirm the reset only when you are finished with your trial requests: it restores sample data and removes uploaded files from this browser.

If the app says browser storage is unavailable, changes are temporary until that problem is fixed. Private browsing or clearing site data can remove the demo. Trying another browser, phone, or address opens a separate workspace.
